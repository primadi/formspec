# In-App Login (di dalam App Surface)

**Tanggal**: 2026-08-21 · **Sequence**: 018
**Plan**: session plan (dev-auth + login redirect) — follow-up

## Apa yang diubah

Memindahkan form login **ke dalam app surface** sehingga login berada di
`/{ws}{root_url}/login` (mis. `/default/app/kafe/login`) dan **tidak lagi
menanyakan workspace** (di-derive dari URL). Sebelumnya login di route
top-level `/login` dan meminta workspace manual.

### `renderers/react-shadcn/src/shell/LoginScreen.tsx`

Tambah prop opsional `workspace`. Jika diberikan (dari URL), field Workspace
disembunyikan dan nilai dipakai langsung. Top-level `/login` tetap meminta
workspace (tanpa prop).

### `renderers/react-shadcn/src/App.tsx`

- `LoginPage` — derive workspace dari `useParams` (route `/:workspace/...`);
  pass ke `LoginScreen`.
- `SurfaceShell` — login route handling: di `{surfacePath}/login`, tampilkan
  form saat unauthenticated, redirect ke surface root saat sudah login. Auth
  guard redirect ke `{surfacePath}/login?returnTo=...` (bukan `/login`).
  Berlaku untuk **app** (`/{ws}/app/kafe/login`) dan **admin**
  (`/{ws}/_admin/login`).
- Loading gate — non-public surface menunggu bundle (agar `root_url` diketahui
  untuk path login yang benar); escape saat bundle ditolak (403 → forbidden).
- Boot effect — guard `!token` agar `boot(token)` dari LoginPage tidak
  ditimpa re-boot anonim (bug: sesi login di-reset ke anonymous); skip reload
  saat `metaError`/`metaForbidden` (cegah infinite loop 403 → reload → 403).
- `handleLogin` — reset meta store setelah login agar bundle dimuat ulang
  dengan permissions user (bundle anonim ber-entities kosong sebelumnya
  di-cache → dashboard error "e.entities is not iterable").

### `renderers/react-shadcn/src/stores/meta.ts`

`load` menangani 403 dari ky `HTTPError` (bukan hanya `FormaApiError`) sebagai
`forbidden` — sebelumnya `_admin` anonim menampilkan "Connection Error"
alih-alih redirect ke login.

### `renderers/react-shadcn/src/shell/LogoutButton.tsx`

Logout navigate ke `{surfacePath}/login` (in-app) via `useSurface`, bukan
`/login`.

## Kenapa

User ingin login berada di dalam app (`/default/app/kafe/login`) dan tidak
perlu mengetik workspace — workspace sudah jelas dari URL.

## Verifikasi

- `tsc --noEmit` + `vitest` (96 tests) lulus.
- E2E browser (dev-auth):
  - App: buka `/default/app/kafe/dashboard/...` → redirect ke
    `/default/app/kafe/login?returnTo=...` (tanpa field workspace) → login
    admin/admin → dashboard render lengkap → logout → kembali ke
    `/default/app/kafe/login`.
  - Admin: buka `/default/_admin` → redirect ke `/default/_admin/login` →
    login → admin render (sidebar modules + entity list) → logout → kembali ke
    `/default/_admin/login`.
