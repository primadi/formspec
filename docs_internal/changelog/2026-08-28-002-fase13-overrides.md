# 2026-08-28-002 — Fase 13.2: Shadow copy (`overrides/`)

## Apa yang diubah

Implementasi §6.4 `08-project-layout.md` (todo 13.2.1–13.2.4) — kustomisasi
presentation vendor module tanpa menyentuh `vendors/`:

- **`internal/vendor/override.go`** (baru):
  - `Adopt` (13.2.1) — `formspec override adopt <module> <kind> <name>`:
    lokasi upstream via loader (bukan tebak path), copy ke
    `overrides/{module}/{kind}.{name}.yaml`, fork-base checksum dicatat di
    `formspec.lock` (`LockEntry.Overrides`).
  - **Whitelist §5.4** — hanya kind presentasi (`Form`, `VisualSpecKind`)
    yang boleh di-shadow; `Entity` dll. ditolak dengan pesan yang mengarahkan
    ke Entity Extension / Integrator. Ditegakkan di adopt DAN di boot
    (`ValidateOverridesDir` — pelanggaran menolak boot, bukan warning).
  - `DiffOverride` (13.2.3) — unified diff shadow vs upstream + flag drift.
  - `CheckDrift` (13.2.4) — bandingkan checksum base vs upstream saat ini;
    warning saat boot (bukan hard-fail, §5.3).
- **Boot wiring** — `overrides/` ditambahkan sebagai manifest root TERAKHIR
  (later roots win → replace-total atas `modules/`/`vendors/`); drift warning
  ke stderr saat boot.
- **`internal/textdiff`** (package baru) — unified diff LCS diekstrak dari
  `internal/consult/diff.go` (kini delegasi) dan dipakai bersama
  `formspec override diff`.
- **CLI** — `formspec override adopt|diff|list`.
- **Fix** — re-install module tidak lagi menghapus record `Overrides` di lock
  (fork-base checksum selamat across version updates); `findUpstream`
  absolutkan base path (CLI default `.` relatif vs loader path absolut).

## E2E terverifikasi (smoke test)

Install vendor → `override adopt billing Form checkout` → edit shadow →
`override diff` menunjukkan perubahan (- upstream, + shadow) → `override list`
→ boot dengan overrides root OK.
