# 2026-09-04-001 — UI "Link {provider}" (explicit OAuth linking)

## Apa yang diubah

Melengkapi todo 5.2.21: UI untuk explicit account linking (backend
`POST /_ui/auth/oauth/{provider}/link` sudah ada sejak 5.2.19).

- **Backend** — `internal/api/oauth_handler.go`: `oauthState` kini punya
  `Mode` ("" = login, "link" = linking). `HandleOAuthAuthorize` membaca
  `?mode=link`; `HandleOAuthCallback` saat mode=link redirect ke SPA
  `/{ws}/_admin/oauth/link-callback#code=...&provider=...` TANPA menjalankan
  `OAuthLogin` (yang akan gagal `ErrAccountLinkRequired` untuk akun password
  verified). `internal/api/meta.go`: `/meta/me` expose `oauth_provider`.
- **Frontend** — `OAuthLinkCallback.tsx` (baru): restore session dari
  sessionStorage, POST `{code}` ke link endpoint (Bearer token), toast +
  kembali ke `_admin`. `LinkedAccountsDialog.tsx` (baru): daftar provider
  terkonfigurasi dengan status Linked/Link; tombol "Link {provider}" →
  full-page navigate ke `authorize?mode=link`. `UserMenu.tsx`: item "Linked
  Accounts". Route `/:workspace/_admin/oauth/link-callback` di `App.tsx`.
  `MeResponse` + `email_verified`/`oauth_provider`.

## Kenapa

User yang kena `ErrAccountLinkRequired` (email verified + akun password)
sebelumnya hanya diberitahu "sign in with your password to link this
account" — tanpa jalan untuk benar-benar link. Kini ada dialog di user menu.
