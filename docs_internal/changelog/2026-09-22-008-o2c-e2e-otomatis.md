# 2026-09-22-008 — Order-to-Cash E2E otomatis (todo 9.2.1)

**Plan/Todo**: item **9.2.1** (`docs_internal/plan/todo.md`).

Rantai Order-to-Cash (order → payment → jurnal GL) **hanya terverifikasi
manual** selama ini: walkthrough skenario 8 di
`examples/kafe/gaps_found/TODO.md` mencatat hasil tangan (`ORD-2026-00021` →
`JRN-2026-000055`, Kas 143750 = Omzet 125000 + Pajak 12500 + Service charge
6250). Konsekuensinya tidak ada apa pun yang gagal bila rantai itu putus.

**Harness** — `resource/o2c_e2e_test.go`. Mem-*boot* app kafe **in-process**
dengan `New(Config{…})` yang sama dengan dev server / native binary (manifest
loading, schema sync, outbox worker, subscription dispatch, Starlark) dan
mendorong rantai lewat **transport produksi**: event durable `on_paid`
diletakkan di **outbox**, worker yang berjalan mengantarkannya ke subscription
`gl`, `journalize.star` menyusun baris double-entry, jurnal ter-posting.

**6 test**:

1. boot in-process — route, registry, dan subscription registry ada; `_meta/version` 200.
2. subscription `gl/journalize` benar mem-*own* `cafe-order.order.on_paid`.
3. transisi `confirm-payment → paid` meng-`emit: on_paid`, dan event-nya
   `publish.durable`.
4. **jurnal seimbang secara numerik** — debit `143750` = kredit `125000 + 12500 + 6250`,
   kas = total pesanan. Sengaja numerik: assert "jurnal ada" akan lolos juga
   untuk jurnal yang tidak seimbang.
5. **idempoten** — event yang sama dikirim ulang (persis retry outbox) tidak
   menggandakan jurnal.
6. pesanan tanpa nilai **ditolak** dan tidak membuat jurnal.

**Dua pelajaran konkret** (keduanya tidak terlihat sebelum ada harness):

- Outbox menerima **nama event pendek** (`on_paid`) plus envelope
  `EventMessage` — handler me-*resolve ulang* deklarasi channel dan menurunkan
  nama fully-qualified sendiri. Meng-enqueue nama fully-qualified membuat
  runtime melaporkan `no channels resolved for cafe-order/order`; jadi bentuk
  luar ini bagian dari kontrak, bukan detail internal.
- Child `lines` hanya ter-*hydrate* lewat `GetByID`, **tidak** lewat
  `FindByField` — pembacaan naif mengembalikan 0 baris padahal jurnal sudah
  ter-posting. Nilai ter-hydrate juga bertipe `[]map[string]any`, bukan `[]any`.

**Catatan jujur**: akun bagan (`gl.account`) di-*seed* oleh test karena kafe
belum mengirim seeder-nya (format `kind: Seed` ada di `formspec seed`, tetapi
kafe tidak memuat file seed). Kode akun yang di-seed harus sama dengan default
`gl_journal_account_*` di `modules/gl/config/gl.yaml` — perbedaan itu adalah
`FORMSPEC.GL.ACCOUNT_NOT_FOUND` yang muncul di percobaan pertama. Seeder kafe
dicatat sebagai item **9.4.1a ⏸️**.
