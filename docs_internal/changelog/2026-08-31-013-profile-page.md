# 2026-08-31-013 — Halaman Profile user (profile_route + custom asset)

## Apa

Menu **Profile** di user menu kini membuka halaman profil user yang sedang
sign-in (bukan lagi \_admin):

1. **`chrome.profile_route`** (`pkg/spec/resources.go`): field baru di
   AppChrome — route in-app ke halaman profil. `registry.yaml` mengisi
   `profile_route: /portal/profile`. Frontend (`ChromeConfig` +
   `UserMenu.tsx`) merender item Profile hanya bila route diset, dan
   menavigasi via `surfacePath(profileRoute)` (workspace-prefixed).
2. **Halaman profil** (`registry/spec/modules/portal/pages/profile.yaml`):
   `mode: custom`, `asset: portal/assets/profile.js`, `public: false`.
   Asset (`assets/profile.js`) fetch `../_meta/me` via `formspec.api`
   (prefix `/{ws}/_ui/entity` menormalisasi ke `/{ws}/_ui/_meta/me`) dan
   merender kartu identitas: avatar inisial, username, user_id, workspace,
   roles, permissions — styling via CSS variables tema (ikut light/dark).

## Fix di sepanjang jalan

- **Asset serving multi-segment**: chi v5 wildcard `{path*}` setelah param
  `{module}` tidak match multi-segment → route diganti `/assets/{module}/*`
  - parse `chi.URLParam(r, "*")` (`internal/api/router.go`, `asset.go`);
    test di-update pakai chi RouteContext (`asset_test.go`).
- **Asset path manifest** harus menyertakan nama module
  (`portal/assets/profile.js`, bukan `assets/profile.js`).
- **Schema JSON di-regenerate** (`make generate-schema`) — schema lama
  stale (menolak `chrome`, `title_visible`, `cache`). Validasi registry:
  13 manifest, 0 problem (dengan `-schema schemas`).

## Verifikasi

- `go build ./...` bersih; `go test ./internal/api ./pkg/spec` 162 pass;
  `vitest src/shell` 11 pass.
- Browser: login TestUser → menu Profile → `/default/portal/profile`
