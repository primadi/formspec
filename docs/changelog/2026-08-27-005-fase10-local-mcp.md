# 2026-08-27-005 — Fase 10.1: `formspec mcp-serve` (local MCP tool server)

## Apa yang diubah

Implementasi `formspec-local-mcp` (todo 10.1.3–10.1.7 + tool grounding
pendukung) sebagai subcommand baru `formspec mcp-serve` (stdio), memakai SDK
resmi `github.com/modelcontextprotocol/go-sdk` v1.7.0:

- **Grounding (read-only)**: `list_kind_schemas`, `read_workspace_manifest`,
  `list_installed_modules`, `read_module_spec` — semua baca via loader yang
  sama dengan engine, bukan tebak path.
- **Validation gate (03 §2/§3)**: `propose_spec_file` selalu validasi otomatis
  (composite tool — caller tidak bisa skip); `validate_spec` memakai package
  yang sama dengan `formspec validate` (`internal/manifest` + JSON Schema
  layer + honesty scan) via `validateSpecTree` — bukan reimplementasi. Draft
  di-overlay ke salinan spec tree supaya referensi lintas-manifest tercek.
- **`apply_draft` (03 §4)**: guard `vendors/` ditegakkan di kode (pesan
  mengarahkan ke Entity Extension / shadow copy), auto-backup ke
  `.formspec/consult/{session}/undo/` sebelum menimpa, re-validate tree
  setelah apply.
- **Kontrol server dev (03 §5)**: `restart_server` (validate dulu → stop →
  spawn `formspec dev` detached, log → `.formspec/consult/server.log` → poll
  `/health`; boot gagal = tail log dikembalikan), `get_server_status`,
  `stop_server`.
- **Skill (06 §2–3)**: `list_skills` (frontmatter name+description) dan
  `read_skill` (Markdown mentah, bukan JSON) dari `AISkillsFS` embed yang
  sudah ada.

## Keputusan teknis

- Path draft = relatif terhadap spec dir (`--spec`); guard `vendors/` juga
  cek project-root untuk layout §6.1 yang akan datang.
- `formspec.lock` best-effort saja (Fase 13 belum ada) —
  `list_installed_modules` scan `modules/`+`vendors/`.
- `sanitizeRelPath` menolak traversal `..` sebelum `path.Clean`.
- Procattr detached dipisah per-platform (`mcp_procattr_unix/windows.go`),
  pola sama dengan `procattr_windows.go` yang sudah ada.
