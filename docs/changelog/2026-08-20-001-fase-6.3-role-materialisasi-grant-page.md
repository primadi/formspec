# 2026-08-20-001 — Fase 6.3 + 5.12.5: Role Entity, Role-Assignment, Materialisasi Grant Page → Permission

## Apa yang diubah

Melengkapi model permission 3-level (App → Page → Action) yang disepakati:
role menyimpan grant page/tab/action, dan grant itu **dimaterialisasi** menjadi
permission string `{module}.{entity}.{action}` konkret saat login.

### 6.3.1 `role` Entity (formspec.core, internal)

- `internal/auth/grant.go` — tipe grant: `Grant` (page → `Actions` untuk block
  page, `Tabs` untuk tabbed page) → `TabGrant` (tab → actions) → `ActionGrant`
  (action + `Conditions` ABAC) → `ConditionGrant` (FormSpecExpr + message).
- `coreRoleSpec()` — entity `formspec.core.role` (name unique, app, description,
  grants JSON). Terdaftar via `RegisterCoreEntities` (internal, tanpa route).
- `internal/auth/role.go` — `RoleStore` membaca role dari entity.

### 6.3.2 `role-assignment` Entity (formspec.core, internal)

- `coreRoleAssignmentSpec()` — entity `formspec.core.role-assignment`
  (user_id, role_id, app, active). Terdaftar via `RegisterCoreEntities`.

### 5.12.5 Materialisasi grant page → permission strings

- `internal/auth/materialize.go` — `Materializer` menurunkan **footprint page**
  (dari blocks/tabs: Form → create/update + custom actions, Table → list/view +
  row/bulk actions) lalu meng-expand grant role menjadi permission strings.
- `internal/ui/meta.go` — ekspor `FormActionPerm` (wrapper `formActionPerm`).
- `internal/auth/service.go` — `permissionsForUser()` menggabungkan permission
  langsung user + materialisasi grant semua role-nya; dipanggil di `issuePair`
  sehingga access token membawa permission termaterialisasi.
- `resource/formspec.go` — wire `RoleStore` + `Materializer` ke auth service.

### Fix pendukung

- Test `resource/ctx_*_e2e_test.go` time-dependent (tanggal hardcoded
  `2026-08-16` kini melebihi backdate limit) → helper `recentDate()` (kemarin).

## Kenapa diubah

Model permission 3-level (App → Page → Action) butuh penyimpanan grant yang
berorientasi page (mental model admin) sekaligus enforcement entity-action
(aman dari confused deputy). Role menyimpan grant page/tab/action; materialisasi
menjembatani keduanya — admin memberi akses per page, framework menurunkan
permission entity-action konkret yang di-enforce server-side.
