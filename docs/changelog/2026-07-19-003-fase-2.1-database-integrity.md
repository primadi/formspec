# Fase 2.1: Database Integrity

**Date:** 2026-07-19
**Plan:** `docs/plan/todo.md` — Fase 2.1 (items 2.1.1 through 2.1.5)

## Changes

### 2.1.1 / 2.1.2 — Atomic mutation, natural-key counter, and outbox
- New `renderers/jsonbpersist/tx.go`: `InTx(ctx, db, fn)` runs `fn` inside one
  `BeginTx`/`Commit`/`Rollback`; nested `InTx`/`BeginTx` calls join the open
  transaction instead of starting a new one (`txDB`/`joinedTx`).
- `EntityStore.Insert`/`Update`/`SoftDelete` (`crud.go`) now wrap their full
  body — natural-key counter UPSERT, row insert/update, child-table sync,
  audit log write, and outbox enqueue — in one `InTx` call. A failure at any
  step rolls back everything, including a natural-key counter increment that
  would previously survive a failed insert as a permanent numbering gap.
- `ChildStore.withDB(txdb)` (new, `child.go`) returns a copy bound to the
  transaction's DB so child-table writes run on the same connection as the
  parent row.
- `InsertParams`/`UpdateParams` gained `PendingEvents []db.PendingEvent`
  (new type). `internal/api/handler.go`'s `HandleCreate`/`HandleUpdate`
  resolve the entity's declared `Emits` event against the pre-mutation data
  and, if durable, pass it in — `EntityStore` enqueues it to
  `forma_outbox` inside the same transaction as the row, via a new
  `enqueueOutbox(ctx, db, ...)` helper (`outbox.go`, used by both
  `OutboxStore.Enqueue` and this atomic path).
- `action.DeliverEvents` (`internal/action/deliver.go`) gained an
  `outboxAlreadyEnqueued bool` parameter; `HandleCreate`/`HandleUpdate` pass
  `true` (the atomic path above already enqueued), `HandleCustomAction`
  passes `false` (unchanged best-effort behavior — **known gap**: custom
  actions don't yet have an atomic mutation+outbox path). New
  `action.BuildEventMessage` factors out the wire-payload marshal so both
  the pre-mutation enqueue and `DeliverEvents` produce byte-identical
  payloads.

### 2.1.3 — UUID v7 PK on both drivers
- New `db.NewUUIDv7()` (`tx.go`, via `github.com/google/uuid`) generates the
  PK at the app layer; `dialectFor` in `ddl.go` now declares `id` as
  `text PRIMARY KEY` (SQLite) / `uuid PRIMARY KEY` (Postgres) with no
  driver-specific `DEFAULT` — the app always supplies `id` explicitly on
  insert. `EntityStore.Insert` and `ChildStore.InsertChildren` generate and
  insert it explicitly. `TableInfo.HasUUIDPK` is now unconditionally `true`.
  `child_test.go`'s manual schema updated from
  `integer PRIMARY KEY AUTOINCREMENT` to `text PRIMARY KEY` to match.
- System tables (`forma_outbox`, `forma_audit_log`, `forma_event_log`) are
  **not** in scope — Core Basic §2's UUID v7 mandate is for Entity PKs, and
  changing these would require unwinding their `last_insert_rowid()`-based
  fallback paths for no contract benefit.

### 2.1.4 — Idempotency retention wired into the running App
- `resource.App` (`resource/forma.go`) now constructs one
  `db.IdempotencyStore` per app, with `WithTTL(cfg.IdempotencyTTL)` (default
  `db.DefaultIdempotencyTTL`, 24h), exposed via `App.Idempotency()`.
  Previously `Config.IdempotencyTTL` was computed in `applyDefaults()` but
  never consumed anywhere — dead configuration.
- Full resolution from a manifest `kind: Config` key named
  `core.idempotency_retention` is **not** implemented — no Config-kind
  registry exists yet (Fase 7.2). `Config.IdempotencyTTL` is documented as
  the equivalent Go-level seam until that runtime lands.

### 2.1.5 — `natural_key_rule` completeness
- `generateNaturalKeys` (`crud.go`) now honors `strategy: custom` — such
  fields are skipped entirely (no counter touched), leaving them to be
  filled by a hook/script/import; `validateRequired` is the backstop if
  nothing fills it.
- `ValidateDocumentSpec` (`pkg/spec/entity.go`) now rejects a
  `natural_key_rule` with an invalid `strategy` (must be `sequence` or
  `custom`) or `reset` (must be `never`/`yearly`/`monthly`/`daily`), and
  rejects `natural_key_rule` declared without `natural_key: true`.
- `format`, `prefix`, `scope_field`, and the composite counter key
  `(tenant, resource, field, scope, period)` were already implemented
  (prior session) — confirmed still correct under the new transactional
  Insert path.

## Known gaps (documented, not silently dropped)
- Custom actions (`HandleCustomAction`) still enqueue outbox events
  best-effort, outside any mutation transaction the action's own impl may
  run — see `docs/renderers/jsonb-persist/01-architecture.md` §3.
- `ctx.next_key(field)` (explicit script call) still always uses
  tenant-wide scope, ignoring `scope_field` — unchanged, pre-existing gap.
- The idempotency two-step prepare flow (`POST /{resource}/{action}/prepare`)
  is not wired to any HTTP route yet (Fase 2.7) — `App.Idempotency()` only
  exposes the store for that future work to consume.
