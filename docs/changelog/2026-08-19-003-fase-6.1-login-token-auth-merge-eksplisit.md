# 2026-08-19-003 — Fase 6.1: Login & Token (Auth) + Merge Eksplisit `external/`

## Apa yang diubah

Menghidupkan alur login + issuance token JWT (access + refresh) di
single-server, dengan **auth entity-backed** di namespace bawaan
`formspec.core` dan **merge eksplisit** yang memungkinkan user override.

### Login & token (todo 6.1.1–6.1.3)

- `POST /{ws}/api/v1/auth/login` — verifikasi kredensial (bcrypt via
  `golang.org/x/crypto`), issue access + refresh JWT.
- `POST /{ws}/api/v1/auth/refresh` — validasi refresh token, **rotate**
  (invalidate jti lama + issue baru); replay token lama → 401.
- Token claims: access (`sub`, `ws`, `roles`, `perms`, `typ=access`, `iat`,
  `exp`, `iss`, `aud`), refresh (`sub`, `ws`, `typ=refresh`, `jti`, `iat`,
  `exp`).
- Dev mode: seed user `admin/admin` otomatis; secret JWT random bila tidak
  dikonfigurasi.

### Entity-backed auth + merge eksplisit

- `formspec.core.user` + `formspec.core.session` didaftarkan sebagai Entity
  built-in (`internal/auth/core.go`) — **internal** (tanpa route API, tanpa
  meta-bundle), hanya diakses framework code via `EntityStore`.
- `SpecInfo.Internal` marker di registry; route generator (UI + custom
  action) skip entity internal.
- `RoleResolver` memetakan peran logis (`user`, `session`) → entity ref.
  Urutan resolusi (user override menang): override eksplisit
  (`SetOverride`/`auth_config_ref`) → `external/` → default `formspec.core`.
- Loader multi-root (`AddRoot`): `external/` di-scan sebagai root tambahan;
  entity di sana menggantikan default `formspec.core` (RegisterCoreEntities
  skip bila sudah ada).
- `formspec generate auth` — scaffold auth module ke `external/auth` untuk
  dikustomisasi.

### Fix pendukung

- `sanitizeIdent` kini mengganti `.` → `_` (module `formspec.core` →
  tabel `formspec_core_*`; sebelumnya dot dianggap database.table oleh
  SQLite).
- `writeJSONValue` kini menangani `[]string` (dan fallback `encoding/json`)
  — sebelumnya slice string menghasilkan JSON malformed.

## Kenapa diubah

Auth adalah prasyarat Fase 6 (permission, roles, API keys, field security)
dan production mode (8.1). Keputusan desain merge eksplisit diambil lewat
diskusi: auth service mengharapkan **kontrak minimal per peran**, bukan
entity spesifik — default `formspec.core` untuk common case, user bisa
override penuh dengan entity sendiri (user override menang).
